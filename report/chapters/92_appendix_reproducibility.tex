\section{Reproducibility manual}
\label{ch:reproducibility}

This appendix is the operating manual: exact commands, exact expected outputs, and the map
from every number in the book to the script that produces it. A reader should be able to
start from a fresh clone and verify every claim.

\subsection{Requirements}

\begin{itemize}
  \item POSIX shell, \code{g++} with C++17 (tested: g++ 12.2), \code{make},
    \code{cmake} $\ge3.20$ (installed user-level by \code{setup.sh} if absent),
    Python $\ge3.9$ (tested: 3.11).
  \item Python packages: \code{numpy}, \code{pandas}, \code{scipy}, \code{statsmodels},
    \code{matplotlib}, \code{seaborn}, \code{scikit-learn}, \code{joblib}, \code{pyyaml},
    \code{reportlab}, \code{yfinance} (the last only if you re-download data externally).
  \item Network: PyPI (for the above). \emph{Not} required for the analysis --- the raw
    price panel is committed under \code{data/raw/yfinance/} precisely so that no
    market-data endpoint is needed at run time.
  \item A TeX distribution (\code{latexmk} or \code{pdflatex} + \code{biber}) \emph{only}
    if you want \code{report.pdf}. The HTML book needs nothing but matplotlib.
  \item Resources used by the full run: $\approx1.5$\,GB disk (mostly
    \code{data/processed/universe.csv}), $\approx1$\,GB peak RAM, 2 cores,
    $\approx12$ minutes.
\end{itemize}

\subsection{The full run}

\begin{verbatim}
# 0. toolchain (idempotent, safe to re-run)
bash environment/setup.sh
export PATH="$HOME/.local/bin:$PATH"        # user-level cmake lives here

# 1. data: raw (committed) -> cleaned panel -> QA gate -> summary tables/figures
python3 scripts/data/clean.py
python3 scripts/data/qa.py
python3 scripts/analysis/make_data_summary.py
python3 scripts/plotting/render_report_data.py

# 2. basket exports for the engine (strictly balanced panels)
python3 scripts/data/export_engine_input.py --target ADBE --basket CRM ADSK INTU
python3 scripts/data/export_engine_input.py --target AVGO --basket ADI INTC AAPL
python3 scripts/data/export_engine_input.py --target GS   --basket BAC
python3 scripts/data/export_engine_input.py --target CAT  --basket HON

# 3. C++ engine + microbenchmarks + unit tests
cmake -S src -B build && cmake --build build -j2
./build/statarbsim --version
./build/statarbsim --test
./build/statarbsim --demo
./build/microbench

# 4. Python test suites
python3 scripts/run_statkit_tests.py
python3 scripts/test_kalman.py
python3 scripts/test_nonlinear.py

# 5. experiments -> results/tables/*.csv  (capture scripts)
python3 scripts/analysis/capture_engine_bench.py
python3 scripts/analysis/capture_backtest.py
python3 scripts/analysis/compare_models.py
python3 scripts/analysis/run_diagnostics.py
python3 scripts/analysis/capture_portfolio.py
python3 scripts/analysis/compare_kalman.py
python3 scripts/analysis/compare_nonlinear.py
python3 scripts/analysis/compare_multtest.py
python3 scripts/analysis/make_statkit_validation.py
python3 scripts/analysis/make_book_tables.py

# 6. results -> figures + report/tables/*.tex  (render scripts)
for s in scripts/plotting/render_*.py; do python3 "$s"; done

# 7. the whole exit gate, then the book
bash environment/check.sh
python3 report/build_report.py
\end{verbatim}

Steps 5--7 are all performed automatically by \code{check.sh} and
\code{build\_report.py}; they are listed individually so that a single artifact can be
regenerated in isolation.

\subsection{Determinism and where numbers legitimately move}

\begin{itemize}
  \item \textbf{Deterministic:} the data pipeline, all hedges, all backtests, all
    diagnostics, and every table. Re-running produces identical CSVs.
  \item \textbf{Seeded-random:} the stationary bootstrap in the Reality Check, SPA, and
    Sharpe confidence intervals (\code{SEED = 11}, $B=1{,}200$, mean block 10). Identical on
    re-run; different if the seed changes, which is why the seed is in the source.
  \item \textbf{Non-deterministic across machines:} the latency and microbenchmark numbers
    (\code{engine\_latency.csv}, \code{engine\_bench.csv}). These are measurements of a
    shared 2-core sandbox and move by tens of percent between runs --- an earlier session
    recorded a regression p50 of $518$\,ns and a \code{deque} ratio of $1.264\times$; builds
    since have recorded $599.5$\,ns and ratios of $1.084\times$, $1.264\times$ and
    $1.333\times$, and a SoA/AoS ratio between $1.033\times$ and $1.509\times$. The tables
    always show the latest run; the prose quotes ranges and mechanisms instead of point
    estimates, precisely because the point estimates are not reproducible to better than
    tens of percent on a shared 2-core host.
\end{itemize}
