# Multi-Asset Statistical Arbitrage

Basket statistical arbitrage via regularized regression, nonlinear extensions, and a
low-latency C++ execution engine — **plus a book-length report of the whole thing,
written from first principles.**

All 14 parts of [`PLAN.md`](PLAN.md) are complete. The deliverable is not a strategy: it is
a reproducible research programme and an honest account of it. The headline empirical
result is deliberately unglamorous —

> On a 195-name, 2010–2026 total-return panel, a causal walk-forward basket spread **does**
> revert (ADF *p* < 10⁻³, OU half-life ≈ 9.4 days, out-of-sample IC ≈ 0.12–0.21), and
> regularized/Kalman hedges improve the net Sharpe from ≈ 0.05 to ≈ 0.09–0.11 at 10 bps.
> But the four-basket book is net-negative over the full sample (net Sharpe ≈ −0.40 to
> −0.46), and **no variant survives a fair correction for the breadth of the search**
> (*M* = 44 audited strategies: Bonferroni survivors = 0, White Reality Check *p* = 0.87,
> Hansen SPA *p* = 0.64, deflated Sharpe ratio 0.31). Structure is established; a
> tradeable magnitude is not.

Every number in that paragraph is regenerated by code in this repository and printed with
its provenance in the book.

## The book

`report/report.tex` is a ~450-page-equivalent treatise in three parts plus appendices. It
assumes the reader knows nothing: Part I builds the mathematics from probability axioms
upwards, Part II walks phase by phase through what was actually built and measured here,
Part III synthesises.

| Part | Contents |
|---|---|
| **I — The Mathematics, From Nothing** | what statistical arbitrage is; probability, returns and why logs; OLS derived four ways; ridge/lasso/elastic-net/PCR with the shrinkage algebra; stationarity, unit roots, spurious regression, cointegration, HAC; the Ornstein–Uhlenbeck process and exact ML; state-space models and the Kalman filter derived from the conditional Gaussian; nonlinear models (GBM/MLP), RESET, learning curves; the arithmetic of backtesting, costs, Sharpe sampling error, drawdown and risk measures; multiple testing, bootstrap, Reality Check/SPA, Diebold–Mariano, power and the deflated Sharpe ratio; cache lines, Amdahl, flop-per-byte and the arithmetic of latency |
| **II — The Project, Phase by Phase** | Parts 0–13: scaffolding, data pipeline and universe, the `statkit` validation suite, the C++ engine, the correctness core, model comparison, diagnostics, the portfolio book, the Kalman hedge, nonlinear extensions, the 44-strategy multiple-testing audit, architecture and measured latency, assembly — each with goal, code map, generated results, honest reading and exit gate |
| **III — Synthesis** | what is established vs. not, ten explicit non-goals with fund-level rationale, the final answer on whether an edge exists, and prioritised future work |
| **Appendices** | twelve extended derivations (ANOVA/F, VIF, LOO, AR(1)↔OU, exact OU ML, Kalman steady state, Sharpe variance, E[max t], participation ratio, a VaR counterexample, water-filling, flop counts); the statkit validation suite and all 35 tests; a reproducibility manual with exact commands and expected outputs; glossary, symbol index, list of figures and tables |

Nothing in it is hand-typed: 24 figures and 23 tables are generated from `results/` by the
checked-in scripts, and each carries a provenance footer naming the script and CSV it came
from.

### Reading it

```bash
python3 report/build_report.py            # regenerate everything, then build the book
xdg-open report/report.html               # or: python3 report/build_report.py --serve 8010
```

* `report/report.tex` (+ `report/chapters/*.tex`) is the **canonical** source. Compile it
  with `latexmk -pdf report.tex` on any machine with a TeX distribution to get the
  paginated book (`report/report.pdf`).
* `report/report.html` is the preview built in-sandbox, where no TeX engine can be
  installed. Math is rasterised locally with matplotlib's mathtext into `report/math/`
  (≈2,000 deduplicated PNGs), so the page needs no network and no CDN. Add `--portable`
  for one self-contained file with figures and math inlined as data-URIs.
* `python3 report/latex_to_html.py --check-math` verifies that every one of the ~3,400
  math expressions in the book is renderable before you build.

## Quickstart

```bash
# 1. toolchain (idempotent; installs cmake/numpy/... user-level)
bash environment/setup.sh
export PATH="$HOME/.local/bin:$PATH"

# 2. data: committed raw CSVs -> cleaned panel -> QA gate
python3 scripts/data/clean.py && python3 scripts/data/qa.py

# 3. C++ engine: build, unit tests, latency demo, microbenchmarks
cmake -S src -B build && cmake --build build -j2
./build/statarbsim --test && ./build/statarbsim --demo && ./build/microbench

# 4. Python research layer + its tests
python3 scripts/run_statkit_tests.py      # 35 tests
python3 scripts/test_kalman.py && python3 scripts/test_nonlinear.py

# 5. every experiment -> results/tables/*.csv -> figures + LaTeX tables -> the book
bash environment/check.sh                 # the full exit gate (52 checks)
python3 report/build_report.py            # regenerate + build report.html
```

Step 5 takes ≈12 minutes and ≈1.5 GB of disk; see
[`report/chapters/92_appendix_reproducibility.tex`](report/chapters/92_appendix_reproducibility.tex)
for the command-by-command manual, expected console output, and the map from every table in
the book to the script that produces it.

## Rules this repository was built under

- **No number without provenance.** Every figure, table and inline statistic is produced by
  a checked-in script from `results/`; the report is *built*, never hand-typed.
- **Walk-forward, no look-ahead.** Hedges are estimated on trailing windows only; targets
  are realised returns over the next *k* bars; hyper-parameters are fixed ex ante.
- **Gross *and* net of cost.** Every Sharpe is reported at 0/5/10/20/50 bps one-way with a
  break-even cost, plus a slippage multiplier stress.
- **Multiplicity is accounted for.** The full search (*M* = 44) is audited with Bonferroni,
  White's Reality Check, Hansen's SPA, a Diebold–Mariano forest, power analysis and the
  deflated Sharpe ratio — and the honest verdict is printed even when it kills the result.
- **C++ is the simulation core; Python is research and plotting only.**
- **LaTeX is canonical; HTML is the preview.** `results/`, `build/` and the rendered book
  artifacts are git-ignored because they are reproducible.
